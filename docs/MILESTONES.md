# Signal Shift — Milestones and Tasks

Source specification: [SPEC.md](SPEC.md). Engine: Godot 4.7.2 (Standard), GDScript.

Each milestone is validated before the next one starts:

- `godot --headless --path . --import` finishes without script errors.
- `godot --headless --path . -s res://tests/run_tests.gd` reports zero failures.
- Changes are committed and pushed to `origin/main` with a message `Milestone N: ...`.

Status legend: `[x]` done and validated, `[~]` partially done (see notes), `[ ]` not started.

---

## Milestone 1 — Project, boot scene, theme, main menu

- [x] Configure `project.godot`: portrait orientation, 720×1280 base viewport, `canvas_items` stretch with `expand` aspect, Compatibility renderer for broad mobile support.
- [x] Add autoloads: `SignalBus`, `SaveService`, `AudioService`, `GameManager`, `SceneRouter`.
- [x] `SceneRouter`: fade transitions, blocks input while a transition is running.
- [x] Theme: generated by `tools/build_theme.gd` into `resources/themes/signal_theme.tres` (deep navy, cyan, electric blue, green, violet, off-white).
- [x] Safe-area aware root container (`scripts/ui/safe_area_container.gd`).
- [x] Boot scene that loads data, then routes to the main menu.
- [x] Main menu: logo/title, Continue, Levels, Daily Puzzle, Puzzle Packs, Settings.
- [x] Reusable `primary_button.tscn` component.
- [x] Lightweight test harness (`tests/run_tests.gd`, `tests/test_case.gd`) — no third-party framework.
- [x] `AGENTS.md` with conventions for Claude Code / Antigravity.

## Milestone 2 — Circuit tiles, rotation, signal solver

- [x] `TileTypes`: directions (up/right/down/left) as bitmasks, base masks per tile type, clockwise rotation.
- [x] Tile types: straight, corner, tee (three-way), cross (four-way), source, destination, blocked, empty; fixed flag.
- [x] `BoardState`: pure data model (types, rotations, fixed flags), rotate, snapshot/restore.
- [x] `SignalSolver`: deterministic BFS from the source, reciprocal-connection rule, stops at blocked cells, visited set (loops safe), returns powered cells and reached destinations.
- [x] `CircuitTile` view: vector-drawn from the connection mask (data is the source of truth), rotation tween, powered state, fixed-tile feedback.
- [x] Tests: rotation, reciprocal connections, traversal, loops, branching, blocked cells, fixed tiles.

## Milestone 3 — Puzzle data, validation, HUD, victory detection

- [x] `PuzzleData`: data-driven JSON level format (tiles, solution, par, optional move limit).
- [x] `PuzzleValidator`: grid dimensions, tokens, source/destination present, fixed/blocked rules, solution solves the board, initial board is not already solved, par/move-limit consistency.
- [x] `PuzzleBoard` view and `PuzzleController` (moves, win detection, single victory event, input lock after win).
- [x] Game scene with HUD: level name, move counter, move limit, reset, undo, hint, pause.
- [x] Victory panel: stars, next level, replay, level select.
- [x] Out-of-moves panel when a move limit is exceeded.
- [x] Tests: validation failures, win detection, duplicate-victory guard.

## Milestone 4 — 60-level campaign

- [x] `tools/generate_levels.gd`: seeded, deterministic level designer. Every level is verified by `PuzzleValidator` before it is written; output is committed as static JSON.
- [x] Difficulty curve per spec (1–10 basics … 51–60 combinations), 6 chapters of 10.
- [x] `resources/puzzles/campaign/campaign.json` — 60 verified puzzles.
- [x] Test: every shipped puzzle validates.

## Milestone 5 — Level select, undo, reset, saving, settings

- [x] `ProgressionData` with versioned save schema, validation and migration of missing fields.
- [x] `SaveService`: atomic write (temp file + rename), backup, graceful recovery from corrupted/missing data.
- [x] Undo restores the exact previous board state (rotations + move count); reset restores the initial board.
- [x] Level select grouped by chapter, locked/unlocked, stars, scroll position preserved.
- [x] Settings: sound, music, haptics, reduced motion, privacy policy link, restore purchases.
- [x] Tests: undo/reset, save/load round trip, corrupted save handling.

## Milestone 6 — Daily challenges and accessibility

- [x] `DailyPuzzleService`: date → puzzle mapping is deterministic, bundled offline content (`resources/puzzles/daily/daily.json`).
- [x] Track daily completion; modest non-premium reward (one free hint token). No streak punishment.
- [x] Daily card on main menu with completion state.
- [x] Accessibility: reduced motion (disables tweens/pulses), colour-independent cues (powered tiles get a thicker line and a node dot, not only a colour change), large touch targets.
- [x] Tests: daily selection determinism, reward granted once per day.

## Milestone 7 — Rewarded ads and IAP service interfaces

- [x] `AdsService` + `AdsBackend` interface; `NullAdsBackend` default (ads unavailable, friendly message, gameplay continues).
- [x] Reward granted only on the backend's reward event; hints flow uses free tokens first, then optional rewarded ad.
- [x] `PurchaseService` + `PurchaseBackend` interface; `NullPurchaseBackend` default (billing unavailable). No simulated purchases.
- [x] Entitlements only come from backend query/restore results, never from a local flag alone.
- [x] Puzzle pack data (`resources/puzzles/packs/`) with manifest, previews, level counts; first level of each pack is a free preview.
- [x] Puzzle pack store screen; ad-free ("Supporter") upgrade with benefits spelled out.
- [x] Tests: reward only on success event, purchase cancel/failure handling, entitlement source of truth (using in-test fake backends).
